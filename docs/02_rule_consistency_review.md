# XianBiz｜跨模块业务规则一致性审查（PRD 编写前）

> 目标：在不擅自推翻 71 项用户已确认选择的前提下，暴露真正矛盾、边界空缺与风险，并给出可编码、可测试的最小解释。对“拟定解释”保持标记，不能冒充用户另行确认。

## 必须写进 PRD 的跨模块约束（拟定解释）

### P0-01｜应收应付形成时点与提前收付的区分（06、07、25、26、65、67、69）

**现有决策**：订单可收付定金、分次收付；收入/成本按实际交付，采购应付按实际收货；提前收到/付出的款不应无货产生收入/采购应付。

**拟定最小规则**：
1. 订单确认时记**合同订单金额**与订/待履约数量；无实际交付/收货时，财务应收或应付为 0。
2. 实际交付生成该交付量对应的应收；实际收货生成对应的应付。
3. 提前收款记录为**预收款**，提前付款为**预付款**；资金实际流入/流出只记一次。
4. 履约时将预收/预付款按明确的分配流水结转抵扣应收/应付；单笔资金可手动分配给多笔债项，包括期初欠款。
5. 期初应收/应付为独立债项，没有伪造历史订单；客户和供应商未结余额需显示清楚预收预付与应收应付的差别。
6. 因第 30 项，匿名散客只能现场已交付、全额结清，不允许保留散客预收/赊欠。

**需防的错**：把“订单金额-已付款”直接当作**当前应收**；把预收款当销售收入；核销 3 张单据重复计 3 笔实际收款。

**验收例**：客户 5,000 元预订，先收 2,000；未交付时销售收入=0、应收=0、预收=2,000；交付 3,000 后收入=3,000、形成应收 3,000，抵扣 2,000 后应收=1,000；剩余 2,000 交付时再产生其应收。

### P0-02｜自动预留、手动补货分配与强制挪用预留（05、29、36、70）

**现有决策**：新订单确认自动预留可用库存；补货后老板手动给历史欠货订单分配；允许警告后强制出库并占用其他客户已预留量；负账面库存允许。

**拟定最小规则**：
1. 维护 SKU 的**有符号账面库存**、按订单分配的**预留明细**、订单待补数量；不能把负账面库存表述为实物真的小于 0。
2. 预留合计不能大于可用于预留的非负现存数量；可销售量按当前账面值减预留计算并最低视为 0 用于普通新单预留。
3. 发生强制挪用时，先在同一个事务中明确减少受影响订单的预留，增加对应欠货量，记录来源、原因，再对当前订单执行出库（可产生负账面库存）。
4. 补货后先处理负账面库存与成本结算，若出现可用正库存，只生成“待手动分配”提醒，不自动分给旧欠货。
5. 若新订单确认时存在历史欠货但老板尚未分配，允许按现有决策自动预留新单**前应提示老板仍有未分配旧欠货**；是否阻止新单不是已确认规则，默认不阻止以免变相自动分配。

**验收例**：SKU 库存 10，客户 A 已预留 10；向 B 强制交付 10 后，库存 0、A 预留 0、A 欠货 10、B 已交付 10，生成风险和预留调整记录；再向 B 强制交付 5，账面库存 -5；后续采购入库 8，账面库存 3，但 **A 不自动获得预留**。

### P0-03｜负库存与移动加权平均成本（12、36、62、63、64、68）

**现有决策**：SKU 移动加权平均；允许负库存，负库存按历史有效平均价暂估、无价时输入，后续补货后校正。

**拟定最小规则**：
1. 不使用 `负库存数量` 直接参与普通加权平均分母；保留最后有效加权平均单位成本与每段未结算负库存出库明细。
2. 负库存发生时冻结每笔暂估成本。后续采购数量先覆盖未结算负库存部分，再将剩余实物数量计入正库存加权平均。
3. 若有多笔负库存出库、不同暂估价与多次补货，按**负库存出库顺序**逐笔结算待核成本（建议作为内部结算顺序，不等于改变正常库存 FIFO 成本法）。
4. 生成成本差异调整流水，关联原销售、对应补货；原出库暂估快照仍保留。
5. 用户第 68 项确定采购运费记经营费用，不计入 SKU 成本；禁止采购货款与运费双重纳入库存。
6. 销售退货依第 63 项恢复或不恢复可售库存，已调整成本的关联关系保持可追溯；库存损失与销售成本不能重复扣除。

**关键风险**：当负库存期间出现**盘点、销售退货、采购退货、强制出库、多个不同进价补货**，必须指定清算顺序并测试，否则会出现负库存补平而毛利不对。

### P0-04｜“边营业边盘点”如何保证账实差异正确（16、37、48、71）

**现有决策**：盘点进行时所有 SKU 可继续正常买卖。

**拟定最小规则**：
1. 盘点单对每条 SKU 记录实际**实物清点时间**，以及该时点的账面库存基准（或者基准时间与此期间流水）。不能仅用“打开盘点页面时间”当作所有 SKU 实盘时间。
2. 确认盘点时根据记录的实盘时点加减其后发生的出入库，计算在确认时刻的等价实存，并只生成**差异调整流水**，不能无条件把库存覆盖为填写的实盘数。
3. 同一 SKU 已盘点、尚未确认期间如果出现无法确定先后顺序的库存变动，应提示重新清点，不能假装系统知道实物何时被点数。
4. 已生效业务时间不可直接回改（71），盘点调整写入实际确认时间并关联实盘依据。

**验收例**：10:00 账面 100，实点 96；10:05 正常卖出 10，账面变 90；10:10 确认盘点，应调整 -4，最后为 86，非 96。

### P0-05｜部分履约后“取消”状态如何表达（02、03、27、28）

**问题**：第 28 项采购状态仅四种（待收货、部分收货、已收齐、已取消），却要求支持“已收到一部分后取消剩余量”，不能把已到货事实改成“全部取消”。销售端也有部分交付后终止剩余部分的同类情形。

**拟定最小规则**：
- 保留用户确认的四个采购**主状态**；用 `remaining_terminated / 终止剩余` 独立标志和 `terminated_quantity`，在 UI 展示“部分收货（剩余终止）”。**不新增第 5 个采购主状态**。
- 无任何收货的订单可处于“已取消”。有收货记录的订单不得抹去已入库流水；终止部分产生完整可追溯变更。
- 销售已交付部分同理；不能仅靠“已取消”隐藏已经发生的收入、库存扣减和收款。
- 终止剩余数量后，已收付定金如超出已履约应收应付，需要继续挂预收/预付，或通过退款冲正结清。

### P0-06｜历史日期不可回改与跨期成本调整（62、65、71）

**现有决策**：销售收入成本按交付日；退货、成本校正应关联原单和调整时间；原生效时间不可直接改。

**拟定最小规则**：
- 原始交易和生效日期均不可修改；后续纠错/退货/成本差异在**实际调整日期**记录独立流水，保留关联原业务。
- 报表区分“本期原始销售毛利”和“本期成本/退货调整影响”，避免无痕覆盖旧期日报。
- 在原订单详情可同时查看“出库原暂估成本、历次成本差异、当前结算后成本”；报表明确采用发生日口径而非伪造历史交易。
- 退款日期按实际退款日期进资金流水，退货对销售净额的影响按实际退货生效日记录，且关联原销售单。

### P1-07｜单机无账号但本地 API 不能任意被攻击（19、22、60、61）

**拟定最小规则**：本地绑定 127.0.0.1、动态端口、单实例；前端与 API 同源提供；校验 Host/Origin，保护状态变更请求，不做通配跨域；不要将“本机访问”误认为完全安全。不得擅加登录页面。

### P1-08｜用户选择基础 REST 及 sqlite3，不代表不需要数据约束（32、47、58、61）

**拟定最小规则**：`PRAGMA foreign_keys=ON` 每连接配置；关键写事务适当 `BEGIN IMMEDIATE`；外键、唯一性、CHECK、索引和幂等键/唯一操作号；业务流水追加而非直接删除；使用整数分、整数件；SQL Schema 版本迁移；SQLite Backup API 一致性备份。

### P1-09｜单据、导出、备份的功能边界（20、23、34、39、52、57、59）

- Excel 是业务数据的可读导出，不是完整恢复介质；备份包含数据库与商品图片、配置、版本信息。
- Excel 初始导入不要求导入完整历史订单；PDF 是浏览器另存，不是 ReportLab 生成。
- 单据只支持文字备注；商品多图应保存本地并进入备份。
- 完整备份需校验数据库与图片一致性，不能直接在 SQLite 正写时裸拷文件；恢复要先保护原数据，避免半完成。

### P1-10｜商品停用、留存和历史价格（09、10、27、32、33）

**拟定最小规则**：历史 SKU、商品、客户和供应商在存在交易引用时不物理删除；允许禁用未来新单选择，历史订单使用提交时价格/商品描述快照；不要让改商品售价影响旧订单。

### P1-11｜费用与库存损益的不可重复计费（26、63、64、68）

- 采购货款进入商品库存价值，**不是**经营费用；采购运费是经营费用（68）。
- 盘亏、不可售退货损耗、报废归库存损益（64），**不可**在经营费用重复生成同额费用。
- 可售退货按对应原销售成本恢复库存；退款反映资金/应收调整，与库存损益分别记账。
- 经营利润是管理口径的简化利润，不可声称是正式会计净利润。

## 建议的上线阻断验收场景（至少覆盖）

1. 全新安装离线进入空白经营后台，无任何默认账号和虚假经营数据。
2. SKU 期初库存导入、成本计算、销售直接交付、费用及毛利报表核对。
3. 订单确认自动预留但未交付不扣库存、不形成销售收入/应收；定金先记预收。
4. 库存不足出现欠货，补货不自动分配；手动分配后交付正确。
5. 抢占其他订单预留并负库存出库，受影响订单欠货正确、记录完整。
6. 负库存多次出库+不同成本多次补货+部分退货，成本结算差异与毛利无重复、可追溯。
7. 分批采购、部分收货后终止余量及多次付款，不丢历史入库记录。
8. 一笔款核销两张订单与一期初余额，现金流水仅记一次；核销失败整体回滚。
9. 可售退货恢复库存，不可售退货形成损耗但不重复扣费。
10. 盘点中穿插销售/收货，确认后只调差额，不覆盖期间流水。
11. 操作重复点击、数据库事务中途报错，无法形成半张单或多次记账。
12. 商品多图和经营数据完整备份恢复，新电脑恢复无引用丢失；PDF 打印、Excel 导入导出在断网环境可用。
13. 程序升级或重装后，`%LOCALAPPDATA%` 的数据库、图片完整保留。
14. 本地 FastAPI 无法从局域网其他主机访问，恶意跨站请求不可执行危险写操作。
15. 1,000 SKU、10,000 历史订单下普通列表、开单、报表流畅可用。

## 对 Codex 的特别说明

用户已经宣布**需求确认结束**。不得再要求用户在 71 项之外大量选择功能，不得按助手历史推荐偷偷替换已确认选项。以上“拟定最小规则”必须在 PRD 的业务规则章节解释清楚、落实为可执行的验收用例；遇到真正不可兼容的逻辑，先形成列明代价的冲突报告，不可擅自删减产品范围。
