## 项目目标和不可妥协的限制

- 最终产品是针对**小型服装批发档口老板**的**真实可用**进销存经营管理软件，不是 Demo/原型/后台页面合集。
- **仅 Windows 单机 PC、完全离线、通过本地浏览器访问**：React + TypeScript + Vite 前端，Ant Design；Python FastAPI + sqlite3 后端，本地 SQLite；PyInstaller 等打包与 Windows 安装程序。Ant Design Charts、openpyxl、浏览器打印 CSS/PDF。
- 安装后双击桌面图标启动本地 127.0.0.1 服务，动态端口、单实例、安全退出；**无任何注册/登录/账号/角色页面**。
- 程序与用户数据分离：程序在标准安装位置，持久化数据在 `%LOCALAPPDATA%\\XianBiz`。图片、配置、数据库均须进入手动完整备份；安装升级不得删除经营数据。
- UI 采用**传统企业软件蓝灰色、紧凑高密度表格、左侧导航右侧工作区**。复杂开单/盘点使用独立页面；轻操作弹窗；详情可用抽屉。
- 用户要求**全部已确认功能一次性完整交付 V1.0，最终统一验收**。这是完整范围要求，不允许悄悄将复杂功能推迟到未来版本，也不禁止你在开发中持续测试。
- 生产默认数据库为干净空白的真实数据环境。允许在隔离的测试环境创建测试数据，但生产界面不得出现 Demo、mock、演示数据和假按钮。不能以静态列表/伪造计算代替业务真实实现。

## 技术实现底线

- 金额使用整数分等精确计算，商品数量按整数件；业务交易采用 SQLite 事务，外键、唯一约束及必要索引；关键确认接口幂等、防重复提交；原始流水追加、错单用冲正而非直接删除。
- 所有关键业务必须在一个后端服务规则内完成，不能前端各页面各自推算余额/库存；库存负数为账面数字，必须按文档记录负库存成本暂估与后续结算，且补货后旧欠货**不自动分配**。
- 无登录不意味着裸奔：仅绑定 127.0.0.1、同源和请求安全验证、防范本机恶意网页跨站写请求；不能擅自添加账号体系。
- 自动暂存开单内容不产生正式业务流水；只有确认提交才生成正式订单与记账。
- 软件运行时不得依赖任何在线字体、图标 CDN、远程 JS、云服务或第三方支付/物流接口；确认断网测试通过。
- 打包可运行所需资源和中文帮助文档；商品图片和 SQLite 数据目录不位于易被升级程序覆盖的安装目录；备份需要考虑 SQLite 正在写入时的一致性。
