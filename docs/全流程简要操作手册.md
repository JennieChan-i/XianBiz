# 纤商全流程简要操作手册

适用：当前开发验收构建。按界面实际入口编写。以下金额在软件界面按“元”输入，数量按“件”；Excel 模板金额按列名要求填写整数“分”。

## 一、先打开独立验收环境

1. 在项目根目录双击 **启动流程验收.bat**。它会打开新的浏览器页面，使用独立数据目录，不改动正式经营数据。
2. 首次设置的店铺名称填写“纤商流程验收”，启用日期用当天。日后再双击此入口继续已有验收数据，不会自动清空。
3. 在 **系统设置 → 备份与恢复** 核对数据目录，结尾应为 `.runtime\manual-acceptance`。正式环境目录为 `%LOCALAPPDATA%\XianBiz`。两个环境可同时运行，请始终核对店铺名称。

## 二、准备最少的测试资料

| 入口 | 资料 | 填写内容 |
|---|---|---|
| 客户往来 → 新增客户 | 客户甲 | 期初应收100元 |
| 客户往来 → 新增客户 | 客户乙 | 期初应收0元 |
| 供应商往来 → 新增供应商 | 供应商甲 | 期初应付0元 |
| 商品资料 → 新增商品 | A001衬衫，黑色 / M | 批发价80元，期初10件，期初成本50元/件 |
| 商品资料 → 新增商品 | B001裤子，蓝色 / L | 批发价100元，期初5件，期初成本60元/件 |

上面A001、B001用于模拟开始使用软件前已有的存货。在新增商品窗口勾选“同时录入期初库存”，输入颜色、尺码，点击“生成颜色 × 尺码矩阵”，再填写期初数量及成本；件数默认空白且必填，无库存填0。保存后打开“详情 / 图片”，上传一张主图和一张附图，再试一次设为主图。条码可选填一个自定测试条码；不要与其他 SKU 重复。

日常首次进货无需先到商品资料建档：进入“采购管理 → 采购开单”，选择供应商，点击“新增商品并采购”，填写商品资料、颜色尺码、本次采购件数和采购单价，点击“保存并加入采购单”。商品会自动出现在商品资料中，保存建档时库存为0；采购单确认“直接收货”后才增加库存，选择“预订 / 待收货”则在后续实际收货时入库。以后补货通过搜索或矩阵选择已有商品，不重复建档。单独在商品资料新增商品时，默认也只建档，不增加库存。

## 三、按顺序跑主要经营流程

请记下采购和销售单号，后续回原单操作。以下第1–5步按上面的空白验收资料顺序执行，才能对得上数值。

| 步骤 | 页面与操作 | 检查结果 |
|---|---|---|
| 1 直接采购 | 采购管理 → 采购开单；供应商甲；A001黑/M，10件×50元；选择“直接收货”；付款200元，运费20元；确认提交。记为采购P1。 | A001库存20件；本单应付300元；运费在经营费用中，库存成本没有加运费。 |
| 2 直接销售 | 销售管理 → 销售开单；客户甲；A001黑/M，3件×80元；选择“直接交付”；收款100元；确认提交。记为销售S1。 | A001库存17件；S1收入240元、成本150元、当前应收140元。客户甲另有期初欠款100元。 |
| 3 预订与定金 | 新销售单；客户乙；A001黑/M，20件×80元；选择“预订 / 待交付”；收定金200元；确认提交。记为销售S2。 | 库存仍17件；S2预留17件、欠货3件；本单尚无收入和应收，有预收200元。 |
| 4 分批交付 | 销售列表打开S2 →“登记本次交付”，先交付5件。 | A001库存12件；S2剩余预留12件、待补3件；本次收入400元，抵定金后应收200元。 |
| 5 补货与手动分配 | 新采购单：供应商甲，A001黑/M，5件×60元，直接收货，暂不付款。记为P2。再回S2 →“手动分配补货”，分配3件；随后交付剩余15件。 | 收货后库存17件，S2仍只预留12件，不自动分配；手动分配后预留15件。全部交付后A001库存2件，S2完成，未结应收1400元。 |
| 6 一笔款核销多笔欠款 | 给客户甲再开一张A001直接交付1件×80元、暂不收款的单S3。在“收付款流水 → 登记收付款”选客户甲，登记320元（如现金120＋微信200），分别核销期初100、S1的140、S3的80。 | 一张资金主流水、两种渠道、三笔核销；客户甲未结应收归零。 |
| 7 采购付款 | 给供应商甲付款600元，分别核销P1的300元和P2的300元。客户乙另收1400元并核销S2。 | 相应应付、应收归零；收付款状态与订单履约状态分别核对。 |
| 8 销售退货 | 回S1 →“退货 / 换货”；先退1件选“可售”，再退1件选“不可售”，填写原因。 | 可售退货加库存；不可售退货不加可售库存，计库存损失；已结清订单产生可退贷项。不要再把损失登记一遍经营费用。 |
| 9 退货退款 | S1详情 →“登记收付 / 退款”，或收付款页面；选“退回预收付 / 退货退款”，登记160元，明确选择两笔退货贷项各80元。 | 贷项结清，只新增实际退款资金流水。 |
| 10 跨款换货 | S1尚可退的最后1件，选择退货并勾选“同时换货”，换B001蓝/L 1件×100元。 | 退货与换货新单关联；原单退货贷项80元，新销售单应收100元。客户甲“核销”分配80元，再收20元核销新单剩余欠款。 |
| 11 采购退货 / 换货 | 回P2，退A001 1件；已付款时会有60元贷项，可登记供应商退款。再从剩余可退量试退1件并同时换入B001 1件×70元。 | 采购退货扣可用库存；换入商品实际入库；核销60元贷项后补付10元。退货前确保SKU没有被其他订单预留。 |
| 12 费用与纠错 | 经营费用 → 登记租金等一笔费用；去收付款流水核对费用支出。再对一笔专门的错误费用或收付款“冲正”，填写原因。 | 原记录保留，另有反向调整记录；费用按归属日进报表，资金按实际登记日进统一流水。 |

注意：已结清订单退货后形成的余额，在当前界面可能显示为“可用预收 / 贷项”，请以来源判断是实际预收还是退货贷项。核销不是再次收钱。

## 四、再覆盖这些分支

| 分支 | 怎样操作 | 看什么 |
|---|---|---|
| 采购预订、预付、部分终止 | 新采购A001 4件×50元，选预订，预付150元；详情先收2件，再“终止剩余”。 | 未收货时无应付；收2件产生100元应付并抵预付，余50元仍为预付；主状态保持部分收货、剩余终止。可再退回50元预付。 |
| 销售取消 / 部分终止 | 一张预订单不交付就终止；另一张先交付一部分再终止剩余。 | 未交付部分释放预留；已交付、收入、收款历史仍保留。 |
| 散客现货与混合收款 | 销售开单不选客户，直接交付一件，现金＋微信合计全额。再试退货或换货。 | 散客必须全额交付并结清；退换货必须当场填准确价差收付，不能留散客欠款或余额。 |
| 草稿、恢复、连续开单 | 开单填入商品但不提交，切换页面或关闭页面，再重新开单；试保存销售草稿、从详情编辑确认；试“确认并新建下一单”。 | 未提交不产生库存/资金流水；可恢复暂存；提交后不恢复成重复单。采购未提交只暂存，不新增采购主状态。 |
| 搜索与扫码 | 开单搜索框输入款号并按Enter；有扫码枪时扫测试条码；用Tab切换数量、价格；再试矩阵一次填多个颜色尺码。 | 加入正确SKU；再次加入同一SKU合并数量；手改售价不会改旧订单。 |
| 主档停用与历史 | 对一个已成交商品/往来档案停用，再查看旧单；试改默认售价。 | 新单不能选已停用主档；旧单描述、成交价及流水仍可查。 |
| 整单冲正 | 单独开一张金额小、没有复杂关联的测试单，再从详情“整单纠错冲正”，填写原因。 | 库存、资金、往来有对应反向调整；原单和原时间保留。存在换货等复杂关联时按界面提示逐笔处理。 |

## 五、重点跑一次负库存

另建商品F001黑/M：期初2件、成本50元/件、售价80元。这样数值不受前面的单据影响。

1. 客户甲预订2件，自动预留2件。
2. 客户乙直接交付3件，不先收款；勾选强制出库、填写原因、确认风险。
3. 检查F001库存为 **-1**；客户甲预留变0、欠货2件；原订单“预留变动 / 操作历史”有记录。
4. 采购直接收货4件×60元。检查库存变为 **3**，客户甲仍没有自动预留。
5. 看客户乙订单“履约与成本”：原始成本150元，后续成本校正＋10元，结算后160元。
6. 给客户甲手动分配2件并交付，库存最后为 **1**。
7. 如需覆盖无历史价场景，另建0库存且未填有效成本的SKU，强制出库时手填暂估价，补货后核对差价。

负账面库存不代表实物真的小于零。以上仅为隔离环境的风险场景验收。

## 六、跑一次边营业边盘点

另建商品T001：期初10件、成本50元/件，保持没有预留。

1. 库存管理 → 新建盘点，选择T001，填写实盘 **8件**，点“立即记录实数与时点”。
2. 暂不确认盘点，去销售直接交付T001 **1件**，账面变9件。
3. 从库存管理 → 盘点记录，回这张盘点单，点“确认盘点差异”。
4. 应只调整 **-2件**，最终库存 **7件**，不能变成8件。
5. 再登记报废1件，填写原因；最终6件，库存流水及库存损益可追溯。

每条SKU实物点数后立即记录。如果页面提示记录期间库存已变化，重新选择并清点。

## 七、导入、打印、报表与备份收尾

1. **Excel期初导入**：系统设置 → Excel期初导入，分别下载商品、客户、供应商空白模板。先用新款号填几行；故意制造重复或负数，确认预览报错且不导入；改正确后预览并确认。不要重复导入前面已建SKU的期初库存。
2. **首页与报表**：检查待交付、欠货、低库存、负库存和往来金额；经营报表选择当天，核对原交付、退货、成本调整、库存损益和费用明细。后续再在另一天做退货/补货，核对调整列在实际发生日，旧日原记录未改。
3. **打印/PDF**：打开订单 → A4打印/保存PDF，检查店铺/单号、商品明细、件数、价格、金额和分页；在浏览器对话框选另存PDF或真实打印机。
4. **Excel导出**：导出报表及全部经营数据，打开文件核对商品、订单、履约、债项、贷项、资金、费用等表。
5. **备份恢复**：仍在“纤商流程验收”环境，创建完整备份并保存ZIP；再新增一笔好识别的测试费用；恢复刚才的备份。应回到备份时状态，新增费用消失，商品图片可打开，并显示恢复前保护副本路径。不要在正式环境做这个回退实验。
6. **退出与重开**：右上角安全退出，再双击启动流程验收.bat；核对数据保留。程序运行时重复双击，确认打开同一验收实例。
7. **断网复查**：断开网络后重开验收环境，试查询、开单、图片、帮助、Excel导出及打印预览。完成后自行恢复网络。

安装、卸载、跨电脑恢复属于单独的部署验收，建议在另一台电脑/测试系统完成。当前手册覆盖业务走查，不等同于这些部署场景已验收。

## 八、发现问题时怎样记录

每项记“通过 / 不通过 / 未测试”。报错时记下：所在页面、订单号或SKU、输入数量/金额、操作顺序、预期结果、实际结果，并截图。提交结果不确定时，先刷新订单/资金列表核对，避免重新开出重复单。

完成后妥善保留验收备份。试单完成不意味着当前开发构建已完成全部商业交付验收。
