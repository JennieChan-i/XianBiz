# 技术设计与数据模型

## 目录

```
backend/       app.py API与安全中间件；db.py 连接/事务/迁移；service.py 业务；files.py Excel/备份/图片
frontend/      React/TypeScript/Ant Design/Charts；独立开单页、表格、抽屉与打印样式
desktop/       单实例、动态端口、浏览器启动、退出、PyInstaller spec
installer/     Inno Setup 安装脚本
tests/         临时目录内的业务/API/性能/备份测试
docs/          基线、PRD、设计、规则、验收、实施记录及离线帮助
scripts/       启动、构建与文档工具
```

## 数据持久化

schema_version 为单调迁移版本；每次连接 foreign_keys=ON、busy_timeout，使用 WAL；写事务 BEGIN IMMEDIATE。settings 保存店铺与启用日等；products 具有款号、分类品牌季节；skus 唯一(商品,色,码)、可空唯一条码、整数库存/价值/最近均价及阈值；images 属于商品。

parties 区分 customer/supplier。orders 与 order_lines 存合同、快照、履约数、退货数、预留数、终止数；fulfillments 保存每次 SKU 履约及冻结成本；negative_lots 保存负库存片段，cost_adjustments 追溯补货结算；inventory_ledger 保存数量/金额/前后库存/来源；reservation_events 保存挪用及分配；returns 保存可售标志和原履约。

debts 为履约或期初债项；credits 为实际资金或退货贷项；allocations 为手动/预付款结转/退货抵扣分配；funds 为真实收付主单，fund_channels 为混合渠道，不建独立账户；expenses 为经营费用。profit_ledger 为发生日损益分录，种类分离收入、销售成本、退货、成本调整、库存损益、费用。stocktakes/items 逐 SKU 保存实盘基准与时间；history 保存关键前后及原因。operations 保存请求摘要、结果 JSON 和幂等号。

## API 协议

GET 读；POST 创建/确认命令；PUT 仅更新主档/店铺/草稿。生效单据不可修改或删除。错误 {error,code}；业务操作请求头 X-Operation-Id 唯一，X-XianBiz-Token 使用启动时令牌。分页 page/page_size、q、排序白名单；所有条件 SQL 参数化。接口校验整数、范围、外键、可用量及业务关联。金额整数分，API 不接收浮点资金。

## 离线与交付

同源静态文件来自 frontend/dist。所有依赖构建进本地文件。PyInstaller 将后端、迁移、前端和帮助文档一起打包；Inno Setup 创建开始菜单、桌面图标，安装到 Program Files。LOCALAPPDATA/XianBiz 保存 SQLite、商品图片、运行状态与日志。退出经令牌保护接口设置 uvicorn should_exit。无后台常驻。完整手动备份 ZIP 使用清单与 SHA256，恢复前保护现状，升级不删除数据。
